--- Action: infra/scripts/switch-to-mirror.sh ---
[1/4] Promoting mariadb-replica to a writable, standalone database...
[2/4] Persisting the promotion in mariadb-replica/conf.d/gtid.cnf (survives a future restart)...
[3/4] Pointing ERPNext at mariadb-replica and restarting the app processes that hold a live DB connection...
[4/4] Arming mariadb-primary/conf.d/gtid.cnf to boot read-only the next time it starts (FR-007)...
Mirror switch complete. ERPNext now runs against mariadb-replica.

NOTE (empirical deviation from a literal reading of the original SQL plan):
the first attempt also tried `SET GLOBAL super_read_only = 0/1`, which
MariaDB 10.6 rejected with "ERROR 1193 (HY000): Unknown system variable
'super_read_only'". MariaDB has no such variable at all (it is MySQL-only);
the script and infra/mariadb-primary/conf.d/gtid.cnf were corrected to use
only `read_only`, which is already sufficient because ERPNext's site DB
user has no privilege beyond its own schema (confirmed via `SHOW GRANTS`).
Documented in full in specs/002-infra-erpnext-replica/research.md.

--- Confirmation of resulting divergence (expected, documented, not hidden) ---
Old primary's SHOW SLAVE STATUS: empty (it was never itself configured as a
replica; it is simply demoted and read-only now).
Old primary does NOT have PUR-ORD-2026-00040 (empty SELECT, no error): it
never saw any write created after the switch, since it was stopped at that
moment. This is the expected, out-of-scope-to-auto-reconcile divergence
discussed in spec.md Edge Cases / Out of Scope (no automatic failover/
failback required). The lab was intentionally left in this post-switch
state; see the final report for the rationale.
