=== Fase 6 evidence: rollback from the Fase-5 mirror switch back to normal
    operation (mariadb-primary writable and active again, mariadb-replica
    following it), done BEFORE capturing the "normal operation" screenshots
    (Evidencias 1-3) so those are not accidentally post-failover ===

--- Starting point (inherited from Fase 5) ---
mariadb-primary: read_only = ON (demoted), not replicating anything
mariadb-replica: read_only = OFF (promoted, active, writable)
backend db_host: mariadb-replica
mariadb-replica SHOW SLAVE STATUS: Slave_IO_Running=No, Slave_SQL_Running=No
  (stale pointer at the old, already-stopped mariadb-primary; error 2003
  "Connection refused" from when the primary container was actually down)

--- Step 1: re-enable mariadb-primary for writes (runtime) ---
$ docker compose exec -T mariadb-primary mariadb -u root -p*** \
    -e "SET GLOBAL read_only = 0; SHOW VARIABLES LIKE 'read_only';"
Variable_name   Value
read_only       OFF

--- Step 2: stop the replica's stale slave thread, then re-run the same
    setup-replication.sh used in US2 (idempotent: CREATE USER IF NOT EXISTS
    + CHANGE MASTER TO + START SLAVE, primary -> replica, same repl_user) ---
$ docker compose exec -T mariadb-replica mariadb -u root -p*** -e "STOP SLAVE;"
$ bash scripts/setup-replication.sh
Creating dedicated replication user on mariadb-primary...
Pointing mariadb-replica at mariadb-primary via GTID...
Replication configured. Run check-replication.sh to verify status.

--- Step 3: restore the replica's read-only protection (its normal role
    while replicating; independent of the promoted-replica state it had) ---
$ docker compose exec -T mariadb-replica mariadb -u root -p*** \
    -e "SET GLOBAL read_only = 1; SHOW VARIABLES LIKE 'read_only';"
Variable_name   Value
read_only       ON

--- Step 4: repoint ERPNext at mariadb-primary again and restart the app
    processes that hold a live DB connection (same mechanism switch-to-
    mirror.sh used, run in reverse) ---
$ docker compose exec -T backend bench set-config -g db_host mariadb-primary
$ docker compose restart backend websocket queue-short queue-long scheduler
(confirmed afterwards: sites/common_site_config.json -> db_host: mariadb-primary)
