--- MSYS/Git Bash finding while building restore.sh (documented in research.md) ---
`docker compose exec`/`cp` calls with a bare argv token starting with "/"
get silently rewritten to a Windows path by Git Bash before reaching
docker.exe (e.g. `mkdir -p /home/...` reports exit 0 but creates nothing,
and even created a literal "C:" directory once inside the container).
Fixed by: (a) wrapping any command that needs an absolute container path
inside a single `bash -c "..."` string, and (b) always using an absolute,
"backend:"-prefixed path as the destination of `docker compose cp` (a bare
relative destination made `docker compose cp` fail immediately with
"Could not find the file sites in container").
